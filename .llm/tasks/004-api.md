# Task 004 — API (FastAPI + WebSocket)

## Objective
Implement the backend API surface for the agentic analytics platform:
- Create/manage runs
- Plan approval gate
- Stream agent events in real time
- Persist datasets/artifacts/events
- Export reports

This task focuses on API shape + plumbing (storage + streaming). Agent logic can remain stubbed as long as the API contract and persistence are correct.

---

## Scope
### In scope
- REST endpoints under `/api/v1`
- WebSocket stream for run events
- DB persistence (runs, events, datasets metadata, artifacts)
- Basic validation + error model
- Async execution hook (enqueue Celery task) — can be stubbed but must change run state and emit events

### Out of scope (for this task)
- Real connector implementations (handled in data-sources task)
- Real analytics computations (handled in agents/analytics tasks)
- Auth/RBAC

---

## API Contract

### Common
- All responses are JSON (`application/json`) unless otherwise stated.
- IDs are UUIDs.
- Timestamps are ISO-8601 UTC strings.
- Error model uses RFC7807-ish `problem+json` style.

#### Problem response
```json
{
  "type": "about:blank",
  "title": "Validation error",
  "status": 422,
  "detail": "Invalid time range",
  "instance": "/api/v1/runs",
  "errors": [
    {"loc": ["body", "time_range"], "msg": "end must be >= start", "type": "value_error"}
  ]
}
````

### 2) Runs

#### Create run (returns proposed plan)

* `POST /api/v1/runs`
  Request:

```json
{
  "query": "Analyse employment trends in the technology sector from 2020–2024",
  "constraints": {
    "time_range": {"start": "2020-01-01", "end": "2024-12-31"},
    "sources_allowlist": ["data_gov_sg", "singstat", "internal_mock"],
    "max_cost_sgd": 2.0
  }
}
```

Response (plan is *proposed*, not executed yet):

```json
{
  "run": {
    "id": "uuid",
    "status": "awaiting_approval",
    "created_at": "2026-01-25T02:00:00Z",
    "query": "...",
    "constraints": {...}
  },
  "plan": {
    "id": "uuid",
    "version": 1,
    "steps": [
      {
        "id": "uuid",
        "agent": "coordinator",
        "action": "select_sources",
        "inputs": {"candidates": ["data_gov_sg", "singstat"]},
        "requires_approval": true
      },
      {
        "id": "uuid",
        "agent": "extraction",
        "action": "fetch_datasets",
        "inputs": {"sources": ["data_gov_sg", "singstat"]},
        "requires_approval": false
      },
      {
        "id": "uuid",
        "agent": "analytics",
        "action": "compute_trends",
        "inputs": {"metrics": ["employment", "yoy_change"]},
        "requires_approval": false
      }
    ],
    "source_rationale": [
      {"source": "data_gov_sg", "why": "demo-friendly stable endpoints"},
      {"source": "singstat", "why": "format diversity (csv/excel)"}
    ]
  }
}
```

Notes:

* The coordinator may use LLMs to draft the plan, but numeric results must not appear here.
* The UI uses this plan for the “review/approve/abort” gate.

#### Approve plan and start execution

* `POST /api/v1/runs/{run_id}/approve`
  Request:

```json
{
  "plan_id": "uuid",
  "approved": true,
  "edits": null
}
```

Response:

```json
{ "run_id": "uuid", "status": "queued" }
```

Behavior:

* Persists approval decision
* Enqueues background task `run_pipeline(run_id)`
* Emits initial events (queued/started) to event store (and therefore WebSocket subscribers)

#### Abort run

* `POST /api/v1/runs/{run_id}/abort`
  Response:

```json
{ "run_id": "uuid", "status": "aborted" }
```

Behavior:

* Marks run aborted
* Worker checks state between steps and stops early
* Emits an event `decision: aborted_by_user`

#### Get run

* `GET /api/v1/runs/{run_id}`
  Response:

```json
{
  "id": "uuid",
  "query": "...",
  "status": "running",
  "created_at": "...",
  "started_at": "...",
  "finished_at": null,
  "selected_sources": ["data_gov_sg", "singstat"],
  "llm_provider_used": "openai",
  "error_summary": null
}
```

#### List runs (history)

* `GET /api/v1/runs?limit=20&cursor=...`
  Response:

```json
{
  "items": [ { "id": "...", "query": "...", "status": "completed", "created_at": "..." } ],
  "next_cursor": null
}
```

## WebSocket

### Subscribe to run events

* `GET /ws/runs/{run_id}` (WebSocket upgrade)

Message schema (server → client):

```json
{
  "type": "event",
  "event": {
    "id": "uuid",
    "run_id": "uuid",
    "agent": "coordinator",
    "phase": "reason",
    "message": "Selecting sources based on query intent",
    "payload": {"intent": {"topic": "employment", "sector": "technology"}},
    "ts": "..."
  }
}
```

Other message types:

* `type: "snapshot"` (optional): sent upon connection with latest run state and last N events
* `type: "heartbeat"`: keep-alive

Requirements:

* Only stream events for that `run_id`
* Sanitise payloads (no secrets, no raw stack traces)

## Persistence

Implement DB models/tables consistent with `/.llm/contracts/db-schema.sql`:

* `runs`
* `plans` (or embed plan JSON in runs if keeping minimal)
* `events`
* `datasets`
* `artifacts`

Minimum required for UI:

* Run status transitions: `awaiting_approval` → `queued` → `running` → (`completed` | `failed` | `aborted`)
* Events persisted before streaming (stream reads from DB insert)
* Artifacts stored as JSON blobs keyed by run_id

---

## Background execution hook

When `/approve` is called:

* enqueue `run_pipeline(run_id)` (Celery)
* worker emits events throughout:

  * coordinator: interpret + plan echo (decision: executing approved plan)
  * extraction: dataset fetch started/completed (even if stubbed)
  * analytics: compute started/completed (even if stubbed)
  * report: rendered
* at completion, persist artifacts and set run status `completed`

Failure behavior:

* If an exception occurs, mark run `failed`, persist `error_summary`, emit `decision: failed`

## Acceptance Criteria

* [ ] `POST /api/v1/runs` creates a run with status `awaiting_approval` and returns a proposed plan
* [ ] `POST /api/v1/runs/{id}/approve` enqueues a worker task and transitions status to `queued`
* [ ] Worker transitions run to `running` and emits persisted events visible via:

  * [ ] `GET /api/v1/runs/{id}/events`
  * [ ] WebSocket `/ws/runs/{id}` streaming the same events
* [ ] `GET /api/v1/runs/{id}/artifacts` returns stored artifacts (stub payloads acceptable)
* [ ] `GET /api/v1/runs?limit=...` returns history with cursor pagination
* [ ] Errors follow problem JSON shape for validation/404
* [ ] No secrets appear in event payloads or error messages
