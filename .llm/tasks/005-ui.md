# Task 005 — UI (Next.js) — Query → Plan Review → Live Run → Results → History/Export

This task implements the **frontend UI** for the Agentic Policy Data Analytics Platform: natural-language query input, **human-in-the-loop plan review**, **live agent event monitoring**, results dashboard (charts/tables/insights with citations), run history, and export actions.

---

## Scope

### In-scope screens (v1)
1. **Home / New Run**
   - Query input (multiline)
   - Source selection (optional toggle list; defaults to recommended)
   - Submit → creates a run and shows **plan review**
2. **Plan Review (Human approval gate)**
   - Show proposed plan steps (readable)
   - Buttons: **Approve & Run**, **Abort**, **Edit** (Edit = minimal inline edits: time range, sources, metrics)
3. **Run Detail**
   - Live agent monitor (timeline / event log)
   - “Artifacts as they arrive” (datasets found, quality warnings, interim tables)
4. **Results Dashboard**
   - Insights list (headline, evidence, confidence, citations)
   - Charts (Plotly) + tables
   - Data provenance section (datasets, endpoints/URIs, retrieved timestamps)
5. **History**
   - List of past runs (status, created time, query snippet)
   - Open a run detail / results
6. **Export**
   - Trigger export (markdown; pdf optional later)
   - Download link (served by backend)

### Out of scope (v1)
- Authentication/RBAC
- Team collaboration features
- Advanced editing of the plan beyond basic fields (time range, sources, top-N)

---

## UX Principles (must-follow)
- **Bounded autonomy + transparency**: always show plan, approvals, and provenance.
- **No hidden reasoning**: display ReAct phases as events (reason/action/observation/decision).
- **Degraded mode friendly**: if LLM narrative fails, still render computed charts/tables and show warning banner.

## Data Contracts (UI-facing)

UI should assume these objects (mirror backend):
- `Run`
  - `id`, `query`, `status` (`queued|needs_approval|running|completed|failed|aborted`)
  - `created_at`, `started_at`, `finished_at`
  - `selected_sources[]`, `error_summary?`
- `Plan`
  - `steps[]` (each step: `agent`, `action`, `inputs`, `expected_output`)
  - `constraints` (allowed sources, time range)
- `Event`
  - `run_id`, `agent`, `phase` (`reason|action|observation|decision`)
  - `message`, `payload`, `ts`
- `Artifacts`
  - `tables[]`, `charts[]` (Plotly specs), `insights[]`, `datasets[]`, `report_md?`, `report_pdf?`

---

## API Calls Needed (Frontend)

Use the backend endpoints defined in Task 004 (API). UI expects:

1. **Create run**
   - `POST /runs` `{ query, requested_sources? }` → `{ run_id, status }`
2. **Fetch plan**
   - `GET /runs/{run_id}/plan` → `Plan`
3. **Approve plan**
   - `POST /runs/{run_id}/approve` `{ edits? }` → `{ status: running }`
4. **Abort run**
   - `POST /runs/{run_id}/abort` → `{ status: aborted }`
5. **Fetch run**
   - `GET /runs/{run_id}` → `Run`
6. **Fetch artifacts**
   - `GET /runs/{run_id}/artifacts` → `Artifacts`
7. **History**
   - `GET /runs?limit=50` → `Run[]`
8. **Export**
   - `POST /runs/{run_id}/export` `{ format: md|pdf }` → `{ url }`

WebSocket:
- `GET /ws/runs/{run_id}` streaming `Event` JSON messages

---

## WebSocket UI Behavior

- Connect when entering `/runs/[runId]`.
- Append events to an in-memory list and also refetch artifacts occasionally (or on certain event types).
- Provide filters:
  - Agent: coordinator/extraction/analytics
  - Phase: reason/action/observation/decision
- Highlight warnings/errors:
  - validation warnings
  - fallback used (LLM or data source)
  - partial completion

## Charts/Tables Rendering

- Charts:
  - Use Plotly React component to render `charts_json` specs.
- Tables:
  - Render tidy tables with minimal sorting and copy-to-clipboard for CSV (optional).
- Insights:
  - Each insight displays:
    - headline
    - evidence values (numbers + pointers)
    - confidence (badge)
    - citations (dataset ids + columns + time range)
  - Clicking a citation scrolls the Provenance panel to that dataset.

## Acceptance Criteria

### Functional
- [ ] User can submit a query and a run is created.
- [ ] UI shows **plan review** and blocks execution until approved.
- [ ] Approve triggers the run and updates status.
- [ ] Run detail page shows **live events** via WebSocket.
- [ ] Results render insights + charts + tables + provenance.
- [ ] History page lists past runs and opens run detail.
- [ ] Export triggers backend and shows a downloadable link.

### UX / Governance
- [ ] Plan approval gate is clear and cannot be bypassed in UI flow.
- [ ] Event stream shows agent + phase with readable timeline.
- [ ] Provenance is visible (datasets, timestamps, URIs/endpoints).
- [ ] Degraded mode: if narrative missing, UI still shows computed artifacts + warning banner.

### Quality
- [ ] No console errors on basic flows.
- [ ] Basic loading/empty/error states for each page.
- [ ] Type-safe API layer (no `any` for core objects).
