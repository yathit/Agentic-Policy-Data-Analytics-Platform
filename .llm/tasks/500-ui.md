# UI Guide (Next.js) - Query -> Plan Review -> Live Run -> Results -> History/Export

This guide documents the **current user-facing UI** for the Agentic Policy Data Analytics Platform. It reflects the implementation in `frontend/` as of now.

---

## Overview

The UI supports a full analysis lifecycle:
1. Submit a natural-language query.
2. Review and approve the execution plan (human-in-the-loop).
3. Monitor live agent activity.
4. Review results (insights, charts, tables) with provenance.
5. Export results and revisit run history.

---

## Pages and Navigation

### 1) Home / New Run (`/`)
**Purpose:** create a new analysis run.
- Multi-line query input.
- Source picker with recommended sources preselected.
- Submit sends the query to the backend and routes to the run detail page.
- Top-right link to **History**.

### 2) Run Detail (`/runs/[runId]`)
**Purpose:** review plan, monitor live activity, and view results.
- Header shows run ID and status badge.
- Query summary with selected sources.
- Error summary banner when available.
- Live activity banner (queued/running/awaiting approval).
- Plan review (approval gate) when needed.
- Event timeline with filters.
- Results tabbed panel (Insights/Charts/Tables/Provenance).
- Export actions when completed.

### 3) History (`/history`)
**Purpose:** view past runs.
- Lists recent runs with query snippet, timestamp, and status.
- Click a run to open its detail page.
- Empty state prompts user to start a new query.

---

## User Workflow

### A) Create a Run
1. Open Home.
2. Enter a query.
3. (Optional) Expand **Data Sources** and adjust selections.
4. Submit to create a run and navigate to `/runs/[runId]`.

### B) Plan Review (Approval Gate)
Shown when a run is in `needs_approval` or `awaiting_approval` status.
- Displays step-by-step plan (agent, action, expected output).
- Edit constraints (optional):
  - Allowed sources (toggle list).
  - Time range (start/end dates).
- Actions:
  - **Approve & Run** (submits optional edits).
  - **Abort**.

### C) Live Monitoring
While running/queued, the UI shows:
- **Live activity status** (active agent + latest action).
- **Connection status** (Live, Connecting, Polling, Error).
- **Agent activity timeline** with filters:
  - Filter by agent: coordinator, extraction, analytics.
  - Filter by phase: reason, action, observation, decision.
  - Expandable payload per event.

### D) Results Review
Results appear in a tabbed panel:
- **Insights**: headline, evidence values, confidence, citations.
- **Charts**: Plotly visualizations.
- **Tables**: tabular data with CSV copy.
- **Provenance**: datasets and retrieval metadata.

**Degraded mode:** if narrative insights are missing but charts/tables exist, a warning banner is shown and computed artifacts remain available.

### E) Export
When a run is **completed**, export buttons appear:
- **Markdown** and **PDF** exports.
- The export opens a new tab to download from the backend-provided URL.

---

## Statuses and Badges
The UI recognizes the following statuses:
- `queued`
- `needs_approval`
- `awaiting_approval`
- `running`
- `completed`
- `failed`
- `aborted`

These are displayed as color-coded badges across the UI.

---

## Data Sources
- The UI requests available sources from `GET /api/v1/sources`.
- If that endpoint is unavailable, a fallback list is used:
  - IMDA Statistics
  - GovTech Open Data
  - SingStat Data
  - External APIs
- Recommended sources are auto-selected on load.

---

## Results and Provenance Notes
- Insights include citations that jump to the **Provenance** tab.
- The current API does **not** return dataset provenance; the Provenance tab is empty until the backend provides datasets.

---

## Live Updates
The run detail page listens for WebSocket events:
- WebSocket endpoint: `/ws/runs/{runId}`
- Message types handled: `event`, `snapshot`, `status`, `heartbeat`.

**Fallback polling:**
- If WebSocket is disconnected and the run is queued/running, the UI polls run status every 5 seconds.

---

## Export Formats
- `md` (Markdown)
- `pdf`

---

## Configuration
- UI connects to the backend using `NEXT_PUBLIC_API_URL`.
- Default base URL: `http://localhost:8000` with `/api/v1` prefix.

---

## Known Limitations (Current Implementation)
- Provenance datasets are not yet returned by the backend; the Provenance tab remains empty.
- No authentication or RBAC in the UI.
- Plan edits limited to **sources** and **time range**.
- No dedicated tests for UI flows (placeholder test script only).

## UI Components (for reference)
- Query input and sources: `QueryBox`, `SourcePicker`
- Plan review: `PlanReviewCard`
- Status and live updates: `RunStatusBadge`, `AgentActivityStatus`, `EventLog`, `AgentTimeline`
- Results: `ArtifactsPanel`, `InsightsPanel`, `ChartsPanel`, `TablesPanel`, `ProvenancePanel`

---

## API Endpoints Used by the UI
All endpoints are under `/api/v1`:
- `POST /runs` (create run)
- `GET /runs/{runId}` (run details)
- `POST /runs/{runId}/approve` (approve plan)
- `POST /runs/{runId}/abort` (abort run)
- `GET /runs/{runId}/artifacts` (results)
- `GET /runs?limit=50` (history list)
- `POST /runs/{runId}/export` (export results)
- `GET /sources` (available sources)

WebSocket:
- `/ws/runs/{runId}` (live events)
